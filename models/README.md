# Models

Trained model files live here at runtime. Binaries are **gitignored** (see
`.gitignore`) — distribute them via GitHub Releases, Git LFS, or a model bucket.

Each detector tries its candidate filenames in order and loads the first one
present, so you can deploy whichever variant you have. The `.hef` (Hailo-8)
files are the primary platform (Pi 5 + AI HAT+); the `*_edgetpu.tflite` /
`*_quant.tflite` files are the Coral/CPU fallback:

| Priority | File | Used by | Notes |
|---|------|---------|-------|
| 1 | `obstacle_model.hef` | `ai/obstacle_detection.py` | **Hailo-8 (Pi 5 AI HAT+), primary** |
| 2 | `obstacle_model_quant_edgetpu.tflite` | " | Coral-compiled (needs Edge TPU) |
| 3 | `obstacle_model_quant.tflite` | " | INT8, CPU TFLite |
| 4 | `yolov8n_obstacle.pt` | " | ultralytics (desktop/debug) |
| 1 | `weed_model.hef` | `ai/weed_detection.py` | **Hailo-8, primary** |
| 2 | `weed_model_quant_edgetpu.tflite` | " | Coral-compiled |
| 3 | `weed_model_quant.tflite` | " | INT8, CPU TFLite |
| 4 | `deepweeds_yolov8n.pt` | " | ultralytics (desktop/debug) |
| 1 | `disease_model_quant_edgetpu.tflite` | `ai/disease_detection.py` | Coral-compiled |
| 2 | `disease_model_quant.tflite` | " | INT8, CPU TFLite |
| 3 | `disease_model_float16.tflite` | " | float16, CPU |
| 4 | `plantvillage_mobilenetv2.tflite` | " | legacy filename |

> **Disease classifier on Hailo:** the disease model is a MobileNetV2 classifier
> (not a YOLO head), so it currently runs through the TFLite/Coral path. A Hailo
> `.hef` classification backend is a straightforward future addition; the YOLO
> detectors (obstacle, weed) are the ones wired to Hailo today.

To produce a `.hef`: on an x86 Linux box install the Hailo Dataflow Compiler,
then `.pt → ONNX (opset 11) → hailomz compile` (or the Hailo Model Zoo retrain
flow). Keep the same base filename (`obstacle_model.hef`, `weed_model.hef`).

Label files (committed, newline-delimited, index order = training order):

| File | Classes |
|------|---------|
| `obstacle_labels.txt` | 7: person, vehicle, animal, rock, stump, fence, ditch |
| `weed_labels.txt` | 2: `crop`, `weed` (`crop` is ignored; only `weed` can trigger spraying) |
| `plantvillage_labels.txt` | 38 PlantVillage disease classes |

`plantvillage_labels.txt` is regenerated by the training notebook from the
sorted dataset folder names — after training, always deploy the notebook's
copy alongside the model.

Training checkpoints kept for future fine-tuning / re-export (never loaded by
the detectors): `weed_best.pt` (yolov8n crop/weed run) and `obstacle_best.pt`
(yolov8n obstacles run); the disease Keras checkpoint lives in
`training/best_disease_model.keras`.

Coral-compiled `*_edgetpu.tflite` files contain a custom Edge-TPU op and will
**not** load on a plain CPU interpreter — that's why each detector falls back
through the CPU variants. The YOLO `.tflite` exports run through
`ai/yolo_tflite.py` (numpy decode + NMS, no ultralytics needed on the Pi).

Camera intrinsics (`camera_intrinsics.npz`, from `ai/camera_calib.py`) also
live here once calibration has been run.

## Versioning & OTA (docs/UPGRADES.md §8)

Releases are described by a `model_manifest.json` (version + per-file sha256)
generated with `py -3.14 pi/ai/model_ota.py make-manifest ...` and uploaded to
a GitHub Release together with the model files. Rovers with
`MODEL_MANIFEST_URL` set in `/etc/agrirover.env` pull updates weekly via
`agrobot-model-ota.timer` — every file is hash-verified before an atomic swap
(previous generation kept as `.bak`; `model_ota.py rollback` restores it).
Full workflow: `deploy/README.md` § Model OTA.
